## 현재 단일 화면 랜딩 (2026-10-17)

하단 네 지표 중 누적 가입자와 누적 직관 기록을 기존 `public_landing_stats()`에 연결합니다. 가입자는 100명 단위(`1,319 → 1,300+`), 직관 기록은 10건 단위(`116 → 110+`)로 내림합니다. 해당 단위보다 작은 수는 실제 값 그대로 표시합니다. 두 번째 지표는 도트 시계 아이콘과 `D+일수`, ‘킥온이 달려온 시간’으로 표시하며 LIVE 지표는 유지합니다. 시작일은 `src/kickon-days.ts`의 `KICKON_START_DATE` 상수(`2026-09-10`)로 관리합니다. 시작일은 D+0이고 한국 시간 자정마다 증가합니다. 첫 표시 시 0부터 현재 일수까지 기존 숫자 카운트업 효과를 적용하고 동작 줄이기 설정에서는 최종값을 즉시 표시합니다. 페이지가 계속 열려 있거나 다른 탭에서 돌아와도 날짜를 갱신합니다.

페이지를 열 때 공개 집계를 조회하고, 응답 후 표시 기준값까지 기존 카운트업을 적용합니다. 요청 제한 시간은 8초입니다. 조회 전·실패 시 `—`를 표시하며 임의의 가입자 상수는 사용하지 않습니다. 집계 범위는 기존과 동일하게 테스트 계정을 제외한 가입·팀 선택 완료 사용자와 그들의 GPS 직관 인증입니다. 서버 함수나 DB는 변경하지 않습니다.

아래 내용은 기존 화면과 집계 API의 도입 기록입니다.

## 표시와 집계 기준

- 사용자 수: 가입 완료, 팀 선택 완료, 테스트 계정 제외. 기존 `public_team_fan_counts()`와 같은 사용자 범위.
- 직관 인증: 위 사용자들이 완료한 `GPS` 경기장 인증. 수동 등록·일일 출석 체크는 제외.
- 숫자는 최소 10단위로 내림합니다. 네 자리에서는 100단위, 다섯 자리에서는 1,000단위입니다. `1,246 → 1,200+`, `87 → 80+`, `9 → 9`, `0 → 0`.
- 페이지를 열면 서버에서 조회합니다. 실패하거나 해당 집계를 사용할 수 없으면 `—`로 표시합니다. 예시 숫자나 임의의 0으로 대체하지 않습니다.
- 새 RPC가 미설치 상태이면 기존 공개 API의 사용자 수만 조회합니다. 직관 인증은 `—`입니다.

## 서버 함수

`supabase/migrations/202610120001_public_landing_stats.sql`은 새 함수 하나를 추가합니다.
`public.public_landing_stats()`는 `user_count`, `attendance_count`만 반환하는 안정적인 읽기 전용 SQL 함수입니다.
원본 프로필·위치·직관 내역을 반환하지 않고 기존 테이블의 RLS나 데이터는 수정하지 않습니다.
정해진 `anon`, `authenticated` 역할에 이 함수 실행만 허용하며 PUBLIC 실행 권한은 제거합니다. 빈 search_path를 사용합니다.
기존 함수가 있을 때는 덮어쓰지 않고 설치가 실패하도록 `create function`을 사용합니다.
되돌리기 파일 `supabase/rollback/202610120001_public_landing_stats.sql`은 새 함수만 삭제합니다.

운영 설치 전에는 함수가 없다는 사실과 집계 기준을 다시 확인합니다. 설치는 운영 변경 승인을 받은 뒤에만 수행합니다.
전체 `db push`로 다른 프로젝트의 마이그레이션을 실행하지 않고, 준비한 함수 파일만 적용합니다.

## 프런트엔드

브라우저에는 publishable 키만 사용합니다. secret/service_role 키를 사용하지 않습니다.
현재 설정은 `sb_publishable_` 형식이며 `apikey` 헤더에만 넣습니다. 사용자 로그인 JWT가 아닌 키를 Bearer 토큰으로 넣지 않습니다.
키 유형은 [Supabase 공식 문서](https://supabase.com/docs/guides/getting-started/api-keys)를 참고하세요.
응답에서 음수·소수·안전한 정수 범위를 벗어난 값과 중복 팀을 거부합니다.
요청은 8초 제한이며 컴포넌트 정리 시 취소합니다. 숫자 영역의 크기를 예약합니다.
