# KickON 랜딩 페이지 리뉴얼 설계

## 1. 목표

KickON 랜딩 페이지가 K리그 팬의 하루를 다음 순서로 전달하도록 개선한다.

1. 오늘의 경기 정보를 확인한다.
2. 라인업과 득점 알림을 받는다.
3. 경기장에서 직관을 인증한다.
4. 경기 결과와 사진 한 장을 기록한다.
5. 시즌별 직관 기록을 확인한다.
6. 실제 KickON 가입 팬과 커뮤니티를 확인한다.
7. 앱을 설치한다.

시각적 화려함보다 실제 앱과의 일치, 가독성, 설치 전환을 우선한다.

## 2. 작업 원칙

- 기존 dirty working tree를 보존한다.
- `git reset`, `git restore`, `git checkout`으로 기존 변경을 제거하지 않는다.
- `src/App.tsx`와 `src/App.css`를 전면 교체하지 않는다.
- 기존 Supabase 팬 집계 로직과 공개 인터페이스를 변경하지 않는다.
- 실제 KickON 앱에 없는 기능이나 가짜 제품 UI를 만들지 않는다.
- 기존 로고, 앱 화면, 팀 엠블럼을 우선 사용한다.
- 신규 UI 또는 모션 라이브러리를 추가하지 않는다.
- KickON 블루를 단일 강조색으로 유지하고 팀별 글로우를 사용하지 않는다.
- 어두운 브랜드 화면 사이에 밝은 기능 소개 영역을 하나의 의도적인 컬러 블록으로 유지한다.

## 3. 디자인 방향

- 모드: 기존 브랜드를 보존하는 점진적 리디자인
- 디자인 변주: 6
- 모션 강도: 3
- 시각 밀도: 4
- 기반: 기존 React, TypeScript, 네이티브 CSS
- 형태: 카드 14-16px, 주요 앱 화면 프레임 24-32px 범위의 일관된 라운드 체계
- 타이포그래피: 기존 폰트 스택을 유지하되 주요 본문은 16px 이상을 기본으로 사용
- 모션: 기존 앱 화면 전환과 상태 피드백만 유지하고 장식용 모션을 추가하지 않음

## 4. 정보 구조

최종 섹션 순서는 다음과 같다.

1. Header
2. Hero
3. 경기 전, 경기 중, 경기 후 기능
4. 직관 기록
5. KickON 가입 팬 현황
6. 커뮤니티
7. 다운로드 CTA
8. Footer

팬 현황은 제품 기능을 이해한 뒤 실제 사용자를 확인하는 소셜 프루프 역할로 이동한다.

## 5. Header

- 좌측 실제 KickON 로고를 유지한다.
- 우측에 `앱 다운로드` CTA를 추가한다.
- CTA는 다운로드 섹션의 `#download` 앵커로 이동한다.
- 데스크톱과 모바일 모두 한 줄을 유지한다.
- 추가 내비게이션 메뉴는 만들지 않는다.
- 키보드 포커스와 최소 44px 상호작용 영역을 보장한다.

## 6. Hero

### 카피

헤드라인:

`K리그의 오늘을 보고,`

`내가 함께한 경기를 기록하세요.`

설명:

`경기 일정과 순위부터 라인업·득점 알림,`

`직관 인증과 나만의 경기 기록까지.`

### 레이아웃

- 정보 우선순위는 헤드라인, 설명, 다운로드 CTA, 앱 비주얼 순서다.
- 첫 화면 안에 모든 요소를 강제로 넣지 않는다.
- 앱 비주얼을 viewport에 맞추기 위해 폰 목업이나 타이포그래피를 과도하게 축소하지 않는다.
- 데스크톱은 텍스트와 앱 비주얼의 2열 구성을 유지한다.
- 앱 비주얼은 현재 수준의 존재감을 유지하거나 소폭 확대할 수 있다.
- 모바일은 헤드라인, 설명, 다운로드 CTA, 앱 비주얼 순서로 배치한다.
- 모바일 앱 비주얼 일부가 첫 화면 아래로 이어지는 것을 허용한다.
- 현재 실제 팀 홈 화면과 직관 기록 화면 전환을 유지한다.
- App Store와 Google Play 실제 링크를 유지한다.

## 7. 경기 전, 경기 중, 경기 후 기능

기존 세 카드와 실제 자산을 유지한다. 번호보다 사용자 여정 단계가 먼저 인지되게 한다.

### 카드 1

- 기본 라벨: `경기 전`
- 보조 번호: `01`
- 제목: `오늘의 경기를 한눈에`
- 설명: `응원팀 경기 일정과 결과, 리그 순위를 빠르게 확인하세요.`
- 실제 인천과 서울 엠블럼 사용

### 카드 2

- 기본 라벨: `경기 중`
- 보조 번호: `02`
- 제목: `중요한 순간을 놓치지 않게`
- 설명: `라인업 공개와 득점 소식을 KickON 알림으로 확인하세요.`
- 실제 KickON 알림 로고 사용

### 카드 3

- 기본 라벨: `경기 후`
- 보조 번호: `03`
- 제목: `내 직관을 기록하다`
- 설명: `경기장에서 직관을 인증하고 오늘의 경기를 내 기록으로 남기세요.`
- 실제 상세 기록 화면 사용

### 카드 정책

- 1200px 이상은 3열, 카드 높이 440px을 유지한다.
- 제목, 설명, 비주얼 시작 위치를 정렬한다.
- 768-1199px에서는 3열을 사용하지 않는다.
- 2열이 콘텐츠 균형을 해치면 1열로 전환한다.
- 767px 이하는 1열이며 데스크톱 고정 높이를 강제하지 않는다.

## 8. 직관 기록

- 제목: `오늘의 함성을 기록으로 남기세요.`
- 설명: `직관 인증부터 경기 결과, 직접 찍은 사진 한 장까지 나만의 기록으로 남겨보세요.`
- 보조 설명: `시즌이 쌓일수록 나만의 K리그 이야기도 함께 쌓입니다.`
- 직관 인증, 사진 한 장, 승·무·패 시즌 기록 항목을 유지한다.
- `public/screens/attendance-history.png`를 사용한다.
- `object-fit: cover`를 사용하지 않는다.
- 이미지 원본 비율을 유지하고 `contain` 또는 이미지 자연 높이로 표시한다.
- 여백은 이미지 크롭이 아니라 프레임의 배경, 패딩, 테두리로 해결한다.
- 승률 차트, 분석 그래프, 가짜 누적 기록을 새로 만들지 않는다.

## 9. KickON 가입 팬 현황

- 제목: `지금 KickON에서 함께 응원하는 팬들`
- 설명: `K리그1·K리그2 팀별 KickON 가입 팬 현황을 확인해보세요.`
- 모든 팬 숫자 문맥에 `KickON 가입 팬`을 사용한다.
- `전체 팬`처럼 K리그 전체 팬 수로 오해할 수 있는 표현을 사용하지 않는다.
- `public_team_fan_counts` RPC, 조회 코드, 정렬, 합계 계산은 변경하지 않는다.
- K리그1과 K리그2 탭, 실제 엠블럼, 내림차순, 로딩, 오류, 재시도를 유지한다.
- 팀 코드와 팀별 컬러 글로우를 노출하지 않는다.
- 모든 팀 카드의 배경, 테두리, 높이, 시각적 무게를 동일하게 유지한다.
- 숫자 자릿수 변경으로 카드 레이아웃이 흔들리지 않게 한다.
- 내부 스크롤바는 현재의 얇고 절제된 방향을 유지한다.

## 10. 커뮤니티

- 제목: `같은 팀을 응원하는 팬들과`
- 설명: `응원팀을 중심으로 경기 이야기를 나누고 K리그의 순간을 함께 즐겨보세요.`
- 구현 전에 `../app/src/features/community/CommunityScreen.tsx`와 최신 실제 스크린샷을 대조한다.
- `ios-qa-07-community.png`는 대조 결과 현재 앱과 충분히 일치할 때만 사용한다.
- 날짜가 더 최신인 실제 스토어 또는 QA 스크린샷이 현재 앱과 일치하면 최신 자산을 우선한다.
- 팀별 강조색이 랜딩 페이지의 KickON 블루 브랜드를 방해하지 않는 자산을 우선한다.
- 적절한 실제 화면이 없으면 이미지 없이 텍스트 중심으로 구성한다.
- 가짜 게시물, 가짜 게시판, 가짜 사용자 활동을 만들지 않는다.

## 11. 다운로드 CTA

- 섹션 ID는 `download`로 설정한다.
- 헤드라인: `다음 K리그 경기는 KickON과 함께하세요.`
- 설명: `오늘의 경기를 확인하고 내가 함께한 순간을 기록해보세요.`
- App Store와 Google Play 실제 링크를 사용한다.
- 헤더 CTA와 최종 CTA의 설치 의도를 동일하게 유지한다.

## 12. Footer

- 브라우저 메타데이터와 KickON 브랜딩을 유지한다.
- 실제 목적지가 없는 이용약관, 개인정보처리방침, 문의하기는 `<a href="/">`로 남기지 않는다.
- 임의 URL을 만들지 않는다.
- 클릭할 수 없는 일반 텍스트 또는 명확한 준비 중 상태로 표시한다.
- 비활성 항목은 버튼처럼 보이지 않게 한다.

## 13. 코드 및 데이터 구조

- `src/fan-data.ts`와 `src/fan-status.ts`의 팬 데이터 흐름을 변경하지 않는다.
- `FanStatusSection`의 상태 전환과 오류 처리를 유지한다.
- 중복된 스토어 버튼은 안전한 범위에서만 재사용 컴포넌트로 정리할 수 있다.
- 페이지 섹션은 현재 `App.tsx` 구조를 우선 유지한다.
- 새 커뮤니티 섹션처럼 독립성이 명확한 부분만 작은 컴포넌트로 분리할 수 있다.
- 단순히 파일이 크다는 이유로 대규모 리팩터링하지 않는다.

## 14. 반응형 기준

다음 viewport를 실제 브라우저 렌더링으로 확인한다.

- 320px
- 375px
- 430px
- 768px
- 1024px
- 1280px
- 1440px

각 viewport에서 다음을 검사한다.

- 가로 overflow 여부
- 헤더 한 줄 유지 여부
- Hero 카피와 CTA 가독성
- 앱 비주얼의 충분한 크기
- 기능 카드 열 수와 내부 정렬
- 직관 기록 이미지 전체 노출
- 팬 현황 카드와 스크롤 영역 안정성
- 커뮤니티 이미지 또는 텍스트 영역 안정성
- 다운로드 버튼 줄바꿈 여부

`overflow-x: hidden`만으로 문제를 숨기지 않고 원인 요소를 수정한다.

## 15. 접근성 및 성능

- 의미 있는 이미지에 정확한 대체 텍스트를 제공한다.
- 장식 이미지는 빈 대체 텍스트를 사용한다.
- 링크와 버튼에 키보드 포커스를 제공한다.
- 본문과 보조 텍스트 대비를 WCAG AA 수준으로 유지한다.
- 이미지 width와 height를 명시해 레이아웃 이동을 줄인다.
- Hero 핵심 이미지는 우선 로드하고 하단 이미지는 지연 로드한다.
- 기존 `prefers-reduced-motion` 처리를 유지한다.
- 브라우저 title `킥온 | K리그 커뮤니티`, favicon, app icon을 유지한다.

## 16. 테스트 및 검증

### 자동 테스트

- 변경된 Hero 카피를 검증한다.
- 섹션 순서를 검증한다.
- 경기 전, 경기 중, 경기 후 라벨을 검증한다.
- 실제 직관 기록 이미지와 원본 비율 표시 정책을 검증한다.
- 커뮤니티 이미지 사용 시 실제 자산 경로를 검증한다.
- 팬 카드가 내부 팀 코드를 노출하지 않는 기존 테스트를 유지한다.
- Supabase 응답 파싱, RPC 요청, 집계, 정렬 테스트를 유지한다.
- Footer가 목적지 없는 `/` 링크를 만들지 않는지 검증한다.

### 완료 명령

- `npm run lint`
- `npm test`
- `npm run build`
- `git diff --check`

### 브라우저 검증

- 7개 요청 viewport를 실제 렌더링으로 확인한다.
- 이미지 로딩 실패를 확인한다.
- 콘솔 error와 warning을 확인한다.
- `scrollWidth > clientWidth` 여부로 가로 overflow를 확인한다.
- 실제 화면 캡처로 레이아웃을 육안 검증한다.

## 18. 완료 조건

- 사용자가 스크롤하면서 경기 전, 경기 중, 경기 후, 직관 기록, 실제 가입 팬, 커뮤니티, 설치 순서를 이해한다.
- 실제 앱과 다른 가짜 UI가 없다.
- 직관 기록 화면이 잘리지 않는다.
- 커뮤니티 화면은 현재 앱과 검증된 자산만 사용한다.
- 팬 집계 데이터 흐름이 변경되지 않는다.
- Footer의 임시 홈 링크가 제거된다.
- 요청한 모든 viewport에 가로 overflow가 없다.
- 기존 자동 검증과 신규 회귀 검증이 모두 통과한다.
- 기존 dirty working tree의 사용자 변경이 보존된다.
